# 模型加载策略文档

> 架构概览参见 [整体架构文档](./ARCHITECTURE.md)，渲染细节参见 [渲染管线文档](./RENDERING-PIPELINE.md)。

## 1. 支持格式对比

### 1.1 格式特性矩阵

| 特性 | .3dm (Rhino) | .gltf/.glb (glTF 2.0) | .obj (Wavefront) |
|------|-------------|----------------------|-----------------|
| **原始几何** | NURBS 曲面 | 三角面片 | 三角/四边面片 |
| **材质支持** | Rhino 材质 | PBR 金属度/粗糙度 | 无（需 .mtl 文件） |
| **纹理嵌入** | 否 | .glb 内嵌 | 否 |
| **压缩** | 否 | Draco 几何压缩 | 否 |
| **坐标系** | Z-up（右手系） | Y-up（右手系） | Y-up（通常） |
| **解析方式** | rhino3dm.wasm | 内置/Draco WASM | 纯文本解析 |
| **文件体积** | 中等 | 小（压缩后极小） | 大（纯文本） |
| **行业应用** | 建筑/工业设计 | Web/游戏/通用 | 通用交换格式 |

### 1.2 格式选择决策树

```
模型来源：
    │
    ├── Rhino / Grasshopper → .3dm（NURBS 精度最高，保留图层）
    ├── SketchUp / Blender / 3ds Max → .glb（Draco 压缩，PBR 材质完整）
    ├── 通用交换 → .obj（兼容性最广，丢失材质）
    └── Web 优化资产 → .gltf
```

## 2. 坐标系转换

### 2.1 Z-up vs Y-up 转换

```
Z-up（建筑 CAD 惯例）          Y-up（Three.js / WebGL 惯例）

        Z ↑                            Y ↑
        │                              │
        │                              │
        │                              │
        └──── Y                        └──── X
       /                              /
      X                              Z

  Rhino, AutoCAD,               Three.js, Unity,
  Grasshopper, GIS              Unreal, glTF
```

Rhino, AutoCAD 等 CAD 软件使用 Z-up；Three.js, Unity, glTF 使用 Y-up。

### 2.2 自动检测策略

ArchViz-Core 采用 **格式元数据优先 + 启发式辅助** 的检测策略：

```
检测流程：

1. 格式元数据判断（最可靠）
   ├── .3dm 文件 → 必定是 Z-up（Rhino 规范）
   └── .gltf/.glb → 必定是 Y-up（glTF 2.0 规范）

2. OBJ 格式的启发式判断（备用方案）
   ├── 计算模型包围盒
   ├── 分析 Y 轴和 Z 轴的范围比
   │   ├── 如果 Z 轴范围 >> X/Y 轴范围（呈"塔"形） → 可能是 Z-up
   │   └── 如果 Y 轴范围 >> X/Z 轴范围（呈"塔"形） → 可能是 Y-up
   └── 不确定时提供用户确认机制
```

### 2.3 变换时机

坐标系转换在加载时执行，通过绕 X 轴旋转 -90° 实现：

```javascript
// 伪代码：Z-up → Y-up 转换
if (format.zUp) {
    modelRoot.rotation.x = -Math.PI / 2  // 绕X轴旋转-90度
    modelRoot.updateMatrixWorld()
}
```

加载时处理的好处：后续所有操作均在统一的 Y-up 空间进行，避免运行时矩阵开销。用户可通过“旋转修正”开关手动切换。

## 3. 单位系统

### 3.1 建筑模型的常见单位

| 单位 | 换算到米 | 常见来源 |
|------|---------|---------|
| 米 (m) | 1.0 | Rhino（取决于模板）、SketchUp |
| 毫米 (mm) | 0.001 | AutoCAD、Revit、工业设计 |
| 厘米 (cm) | 0.01 | 部分 Blender 导出 |
| 英寸 (in) | 0.0254 | 美国建筑实践 |
| 英尺 (ft) | 0.3048 | 美国建筑实践 |

### 3.2 自动缩放校准

当前通过用户确认机制选择单位。自动检测的设计方向：

```
自动单位推断算法（启发式）：

1. 计算模型包围盒的最大维度 maxDim
2. 推断原始单位：
   ├── maxDim ∈ [0.1, 500]    → 可能是米（建筑尺度合理）
   ├── maxDim ∈ [100, 500000] → 可能是毫米（除以1000后合理）
   ├── maxDim ∈ [1, 5000]     → 可能是厘米（除以100后合理）
   └── 不确定时弹出用户确认
3. 辅助判断：
   ├── 如果存在已知尺寸的参考物（如门高约2.1m）
   └── 如果文件元数据中包含单位信息（部分格式支持）
```

### 3.3 毫米到米的转换

对模型根节点应用均匀缩放，在 `processModel()` 最早阶段执行，确保后续操作基于正确尺寸：

```javascript
// 伪代码
if (unit === 'mm') {
    root.scale.set(0.001, 0.001, 0.001)
}
```


## 4. 性能优化

### 4.1 高多边形检测

```
顶点数量分级：

  < 200万   → 正常流程，无提示
  200万-500万 → 显示警告弹窗，提示可能卡顿
  > 500万   → 建议进行减面优化后再加载
```

**200万顶点预警阈值的依据**：主流移动 GPU 在 100-200万三角面时开始帧率下降；超过此阈值后阴影和后处理开销显著增加。

### 4.2 几何体优化

模型加载后执行以下优化步骤：

```
遍历所有子节点：
    │
    ├── 检查法线 ── 缺失则调用 computeVertexNormals()
    │               （PBR 光照依赖法线数据）
    │
    ├── 清理顶点色 ── deleteAttribute('color')
    │                 （避免与材质颜色冲突）
    │
    ├── 启用阴影 ── castShadow = true, receiveShadow = true
    │
    ├── 备份材质 ── userData.originalMat = material.clone()
    │               （支持风格预设后恢复原始材质）
    │
    ├── 禁用视锥裁剪 ── frustumCulled = false
    │                    （建筑模型通常始终在视野中）
    │
    └── 记录初始变换 ── userData.initPos / initRot / initScale
                        （支持"重置位置"功能）
```

### 4.3 LOD 策略考量

当前未实现 LOD。建筑可视化 LOD 的特殊性：建筑几何以直线和平面为主，简化不应引入曲面误差；轮廓线是识别建筑的关键，LOD 切换不应改变轮廓；正交相机下应使用屏幕面积而非距离作为切换依据。

### 4.4 WebWorker 异步加载

rhino3dm.wasm 的 NURBS 镶嵌和 Draco 解压缩是 CPU 密集型操作。更进一步的优化方向是将 `processModel()` 移入 WebWorker，挑战在于 Three.js 对象不可直接跨 Worker 传递，需通过 Transferable 对象中转。

## 5. Rhino 格式深度解析

### 5.1 rhino3dm.wasm 的加载机制

Rhino3dmLoader 依赖 `rhino3dm.wasm`，这是 openNURBS 库的 WebAssembly 编译版本。加载流程：

```
Rhino3dmLoader.setLibraryPath(cdnUrl)
    │
    ▼
首次调用 load() 时：
    ├── 下载 rhino3dm.wasm (~2.5MB)
    ├── 实例化 WASM 模块
    └── 缓存到内存（后续加载不重复下载）
    │
    ▼
解析 .3dm 文件：
    ├── 读取文件头：版本号、单位、坐标系
    ├── 提取对象表：几何体、图层、材质、用户数据
    └── 逐对象转换为 Three.js 几何体
```

CDN 路径使用 jsDelivr 托管的 rhino3dm@8.4.0 版本，确保全球加速和版本锁定。

### 5.2 NURBS 到 Mesh 的镶嵌

Rhino 原生几何是 NURBS 曲面，WebGL 只能渲染三角面片。镶嵌在 WASM 中完成：

```
NURBS 曲面
    │
    ▼
参数域采样 ── 在 u-v 参数空间中生成采样网格
    │
    ▼
求值 ── 对每个 (u,v) 点计算 3D 坐标、法线、切线
    │
    ▼
三角化 ── 将采样网格转换为三角面片
    │
    ▼
法线平滑 ── 基于曲面连续性计算顶点法线
    │
    ▼
Three.js BufferGeometry
```

镶嵌精度由 rhino3dm 内部公差参数控制。建筑几何以平面为主，默认精度通常足够。

### 5.3 图层、材质与用户数据的提取

.3dm 文件不仅包含几何体，还携带丰富的元数据：

- **图层信息**：建筑模型的图层组织（如"墙体"、"楼板"、"幕墙"）
- **材质属性**：Rhino 的渲染材质（漫反射色、透明度等）
- **用户数据**：Grasshopper 参数化设计附加的自定义属性

当前加载时提取材质信息（存入 `userData.originalMat`），图层和用户数据尚未充分利用，为未来按图层过滤、属性查询等功能提供基础。

### 5.4 线段几何的特殊处理

Rhino 模型中常包含曲线/线段（如辅助线、标注线）。这些被转换为 `THREE.LineSegments`，需要特殊的材质处理：

```
遍历加载结果中的线段对象：
    │
    ├── 检查线段颜色
    │   ├── 如果为纯黑 (0,0,0) → 替换为深灰 (0x333333)
    │   │   （纯黑线段在黑色背景下不可见）
    │   └── 否则保留原始颜色
    │
    └── 设置 LineBasicMaterial
        （线段不参与阴影和后期处理）
```

## 6. 加载重试与代理回退

网络环境的不确定性要求加载管线具备容错能力：

```
load(url)
    │
    ├── 直连尝试
    │   ├── 成功 → 进入 processModel()
    │   └── 失败 → 启动代理回退
    │
    ├── 代理 1 (corsproxy.io)
    │   ├── 成功 → 进入 processModel()
    │   └── 失败 → 尝试下一个代理
    │
    ├── 代理 2 (codetabs.com)
    │   ├── 成功 → 进入 processModel()
    │   └── 失败 → 尝试下一个代理
    │
    └── 代理 3 (allorigins.win)
        ├── 成功 → 进入 processModel()
        └── 失败 → 报告错误，建议用户检查网络
```

通过代理 URL 加载时，需要从代理 URL 中提取原始文件扩展名，以正确选择加载器。这是一个容易被忽视的边界情况。

---

## 技术要点

1. **加载时坐标系统一**：格式元数据驱动的自动 Z-up → Y-up 转换，避免后续剖切/光照/阴影方向错乱。

2. **材质备份模式**：加载时 `clone()` 备份原始材质，风格预设切换后可无损恢复（Memento 模式）。

3. **渐进式容错加载**：直连 → 代理 1 → 代理 2 → 代理 3 的回退链，确保各种网络环境下的加载成功率。

4. **性能阈值选择**：200万顶点预警基于目标设备 GPU 能力、WebGL 限制和典型建筑模型复杂度的综合考量。
